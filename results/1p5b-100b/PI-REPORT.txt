NOTES AND CAVEATS
================================================================================

NOTE 1 -- SIZE LABEL.  Report this as 1.7B, not 1.5B.  The non-embedding body is
  exactly the specified architecture (1,491,045,752 params).  The config named
  vocab_size 32,000, which would give 1,540,197,752 total; the only 100B shard
  available is Llama-3.1, whose 4x larger vocabulary adds 147,849,216 embedding
  parameters.  Non-embedding count is bit-identical either way.

NOTE 2 -- COMPARISON TO MAMBA-3.  Mamba-3's "1.5B" row is d2048/L48, which at
  vocab 128,256 is 1,470,627,840 total / 1,207,959,552 non-embedding.  We are
  +15% on total and +23% on non-embedding parameters, so any favourable
  comparison is partly a capacity effect and should be stated as such.

NOTE 3 -- PERPLEXITY IS TOKENIZER-DEPENDENT.  The 9.693 figure is comparable
  only to models using the same Llama-3.1 vocabulary, and is measured on our own
  held-out split rather than anyone else's.  The downstream accuracies are the
  tokenizer-independent numbers and are the safer basis for comparison.

NOTE 4 -- TASK PROFILE IS THE FINEWEB-EDU SIGNATURE.  ARC-Easy at 76.1% is high
  for this scale (Mamba-1.4B on 300B Pile tokens reports ~65%), while LAMBADA at
  50.9% is lower than that same model (~65%).  This is the expected result of
  training exclusively on an educational-filtered corpus: the distribution is
  close to ARC-style science QA and largely excludes the narrative fiction that
  LAMBADA tests.  Worth stating pre-emptively.

NOTE 5 -- LEARNING RATE WAS NOT SEARCHED AT THIS SCALE.  1.7e-3 was chosen from
  a least-squares fit through the three interior LR optima of our earlier sweeps
  (d128 -> 0.00752, d384 -> 0.00483, d640 -> 0.00256; lr ~ 0.167*width^-0.627,
  giving 0.00168 at d1536).  The curve was stable throughout and the cosine
  anneal delivered the expected late gain (2.50 -> 2.33 over the final 20%), but
  this is an extrapolated value, not a measured optimum.

NOTE 6 -- NO MATCHED BASELINE.  Nothing here supports a claim that SKA beats
  Mamba-2; that requires a control run on the identical protocol.  What our
  earlier sweeps do establish is that the SKA path is load-bearing WITHIN this
  architecture: ablating it at evaluation raised loss in 1,262 of 1,262
  completed trials across four model scales.

NOTE 7 -- WHICH METRIC.  Where a task defines both acc and acc_norm we print
  both, and the average uses the Mamba-paper convention (acc_norm for HellaSwag
  and ARC-Challenge, acc elsewhere).  WinoGrande, BoolQ and LAMBADA define only
  acc in lm-evaluation-harness -- acc_norm length-normalises the candidate
  log-likelihoods, which is meaningless when the candidates are equal-length by
  construction (WinoGrande), "no"/"yes" (BoolQ), or a single continuation
  (LAMBADA).  All six tasks ran to completion; nothing is omitted.

NOTE 8 -- CODE PROVENANCE.  The run's own spec records
  git_commit 42749a8e with `dirty: true`: the working tree carried uncommitted
  changes at launch, so that commit alone does not reproduce this run.  The
  changes in effect were the multi-node DDP fixes (srun + c10d rendezvous,
  --cpus-per-task, SIGUSR1 forwarding, exact-resume, checkpoint pruning) and,
  critically, a DistributedSampler fix: it had been given the LOCAL rank, so on
  8 nodes every node would read the same eighth of the shard.  This run has the
  fix and did train one true epoch.  The full resolved spec is committed
  alongside this report as spec.yaml.
