## 7. Findings a collaborator needs to hear

- **Published Table 2 numbers are superseded.** `table2.py` built AdamW with flat
  `model.parameters()`, decaying norms, biases, embeddings and the Mamba state
  params. Measured impact: **~2.04-2.12%** of parameters at `1m`.
- **MQAR fine-tune numbers likewise, and worse:** **~24.65%** of parameters at 50m,
  at 10x the intended decay coefficient.
- **The README's parameter count was wrong.** 50m is **50,034,044**, not the quoted
  50,765,216 — a 1.46% overcount from four errors in `param_count_estimate`, chiefly
  mis-sizing Mamba-2's `in_proj` (B and C project from `d_model`, not `d_inner`, with
  `ngroups=1`) and omitting Mamba2's internal `RMSNormGated`. Now bit-exact against a
  real instantiation.
- **`build_transformer` initialised embeddings at std ~1.0 instead of 0.02** — pure
  omission, `_build_model` only branched on `init_policy == 'mamba_safe'`. **No rerun
  needed:** it is unreachable from any trainer (not in `train.py`'s `--model_type`
  choices, not in `table2.py`'s `MODEL_BUILDERS`), so nothing was ever trained with
  it.
- **`table2.py` trains in fp16 + GradScaler** while the other two use bf16. A real
  numerics difference nobody had noted; unifying it moves Table 2's numbers.
- **The two loss conventions genuinely disagree by ~0.55 nats** on shared curricula
  data, because they assume opposite label-alignment conventions. Now covered by a
  test so the trainer merge cannot get it wrong silently.
