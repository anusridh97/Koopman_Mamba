## 2. Hard constraints — violate these and you break something silently

**Never install into `/users/jkli/.venvs/koopman-cpu`.** Its `site-packages` must
stay byte-identical. Anything new goes to a separate dir via
`pip install --target`.

**Never run bare `git stash` / `git stash pop`.** The stash stack is shared across
every worktree in this repo. A bare `pop` on 2026-08-21 pulled in a *half-resolved
cherry-pick with conflict markers already baked in*, produced nested markers two
generations deep, and left `spec.py` and `train.py` as SyntaxErrors. Use
`git stash push -m "<tag>"` and `git stash apply <sha>` if you must.

**`metrics.py` must import with optuna absent.** Its optuna import is lazy at
`:362` on purpose — the OOM ladder and log parsing have to work without it, and
hard-importing broke the CPU suite once. `sweep/search/__main__.py` never imports
optuna either, which is what lets `--dry_run` print a full plan on a laptop.

**`read_quick_eval_objective` stays `(run_dir) -> float|None`.** Do not widen it
to take `(study, trial)`. Use `metrics.fixed_reader` to adapt it to the driver's
factory-shaped `objective_reader_for`.

**`runtime` is not hashed into `run_id`.** `run_id = sha256(model + data + optim +
seed)`. Adding a `runtime` field is safe; adding an `optim` field renumbers every
archived run. Check with: `4m-golden.yaml` must stay `run_id 2e63f16e` /
`group_id d812e412`.

**GPU gates read `SLURM_SUBMIT_DIR`, not `BASH_SOURCE`.** sbatch copies the script
to a spool dir, so `BASH_SOURCE` is `/cm/local/apps/slurm/var/spool/...`. Always
`sbatch` from the repo root. The scripts validate this and exit 1 if the resolved
root has no `experimentation/` and `code-tests/`.

## 3. The verification apparatus — this is the part that matters

Four **bit-exact golden curves**, all with a `0.000000` noise floor:

| golden | trainer | captured with |
|---|---|---|
| `golden_4m_curve.json` | `train.py` (shard) | `runtime.deterministic: true` |
| `golden_mqar_curve.json` | `mqar_finetune.py` | `--deterministic` |
| `golden_table2_curve.json` | `table2.py` | `--deterministic` |
| `golden_resume_curve.json` | `train.py`, interrupted at 266 and resumed | `runtime.deterministic: true` |

Run them with `sbatch scripts/verify_goldens_after_refactor.sbatch` (mqar +
table2, ~10 min) and `sbatch scripts/capture_resume_golden.sbatch` (4m + resume,
~13 min).

**What the floor means.** The progress line prints `loss %.4f`, so 1e-4 is the
smallest representable difference and `compare_golden_curve.py`'s `MIN_TOLERANCE`
is exactly that. "Floor 0.000000" means *identical at the printed resolution*, not
to arbitrary precision.

**Why they are load-bearing.** `train.py`'s loop was at 29% line coverage for its
whole life. Every substantive finding on this branch came from a golden, not from
the CPU suite:

- the table2 migration passed 1379 CPU tests and still moved the curve by 8e-4,
  because the per-task loss split had drifted inside `autocast` (which promotes
  `cross_entropy` to fp32);
- the resume golden's first run found the running-loss *window* wasn't carried
  across a checkpoint;
- the old 4m "noise floor" of 2e-4 turned out to be pure nondeterminism, hiding
  everything below it.

**So: any change to a training loop is unverified until a golden says otherwise.**
`code-tests/test_training_loop.py` now executes the shared loop on CPU in under a
second and catches structural breakage (accumulation arithmetic, LR-schedule
cadence, scaler ordering, checkpoint cadence) — but it cannot see precision or
kernel changes. It is a fast filter, not the gate.

## 6. Failure patterns this codebase actually produces

Read this before writing a guard; the same four shapes keep recurring.

**Valid, validated, and inert.** A config field that is accepted, type-checked,
and read by nothing. `ska_backend` is read by exactly one of four SKA routes;
`chunk_strategy` / `overlap_fraction` / `decay_alpha` have no reader at all; §6/§7
re-landed with 93 passing tests while nothing called them. Unit tests of a
mechanism cannot see that nothing invokes it. `test_extensions_are_wired.py` is the
counter-pattern.

**A hardcoded roster that silently goes stale.** `test_progress_log_format.py`
enumerated two trainers and missed table2; the flush test was hand-edited twice for
the same non-reason. Both now *discover*, and absorbed three migrations with no
edits. Prefer discovery, and always add a guard-the-guard assertion — a glob that
matches nothing makes every parametrised test vacuously green.

**Signature drift swallowed by a broad `except`.** `launcher.submit` grew `wait`;
three test stubs didn't; the `TypeError` was caught by the OOM ladder's
`except Exception` and surfaced as `assert 'failed' == 'complete'`. 22 tests failed
with the real cause visible nowhere. Related: `__main__.py` kept passing a removed
keyword and *nothing caught it*, because `--dry_run` returns before `drive()`.

**A test that passes for the wrong reason.** `torch.is_autocast_enabled()` with no
argument reports on **CUDA**, so a CPU-autocast probe silently returned False. The
archived-resume test used a base config where the wrong implementation coincided
with the right one. **Always break the code and watch the test fail** before
believing it.

## 7. Orchestrator notes

**Worktrees fix the real problem.** Today's mess was two agents in one worktree
plus a shared stash. Per-worktree isolation also *improves* the provenance guard,
since each tree is clean independently. The gate scripts are now path-independent,
so a subagent can verify its own tree.

**But parallelism has a ceiling.** The gates are GPU jobs and the cluster
serializes them. Four subagents wanting goldens is four queue slots, not 4×
throughput. The parallelism you actually gain is in analysis and implementation,
not verification.

**What decomposes and what doesn't.** Well-specified independent tasks work well —
so do investigations (the SKA kernel measurement and the token-viewer study both
came back with real findings). Exploratory refactors do not: the loop
unification needed four seams and **every one was discovered while doing the
work**. A subagent handed "migrate table2" would have hit the autocast precision
bug with no golden intuition to recognise it.

**Housekeeping worth doing.** 27 worktrees exist, most on stale branches; one is in
`/tmp/claude-851721614/...` and won't survive a reboot. `stash@{0}` is the
"aborted PR B cherry-pick" entry — PR B's content is now landed on this branch, so
that stash is safe to drop and is the exact landmine that caused today's nested
conflicts. `docs/gen_inventory.py` is an untracked scratch script left by another
agent; it walks `koopman_lm`, a pre-split assumption.
