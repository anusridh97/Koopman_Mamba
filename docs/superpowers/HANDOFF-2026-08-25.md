## The four measurements that constrain everything downstream

Cited by job so they can be re-derived, not trusted.

1. **The noise floor is a hard ceiling, and a longer horizon does not lift it.**
   sigma = 9.50e-3 at 600 steps (job 445832) and 7.54e-3 at 1500 (job 445994),
   five seeds each. sigma is a near-constant 0.17-0.18% of the loss at both, so
   more steps buys resolution only as fast as it buys loss. Trial-vs-trial
   resolvable effect at 1500 steps is 0.0213; mean-vs-mean at n=6 is 0.0087.

2. **Held-out LM loss cannot see SKA damage.** Destroying 44% of SKA's
   contribution moved mean loss by 0.00016 — *downward* — far below the floor
   (jobs 446363-446420). So a change can gut the mechanism and be invisible in
   aggregate loss. **Any SKA design question must be asked of a structured task,
   not of LM loss.** This is the single most consequential result of the session.

3. **SKA is load-bearing, and the 4m reading that suggested otherwise was a
   scale artefact.** Ablation delta 0.025139 +- 0.002976 SEM over five seeds,
   t = 8.4 (job 445994, 8-batch `quick_eval`). At 4m the same measurement gives
   1.17e-4 — 100x smaller. **Name which statistic you mean:** the 64-batch
   harness figure for the same runs is 0.016402, and the two give different
   verdicts on marginal contrasts.

4. **Most registry configs run the approximate chunked SKA route**, and the
   "~100% relative error" warning that disclaims them had no artefact behind it
   until this session (it traced to a bulk-import commit). Goldens and
   loss-ranked searches on those configs are safe; mechanism claims are not.
   Above 370m there is no exact route that runs at all.

## Not started, deliberately

**The 256-trial interaction study** (`configs/search/proxy-256x17-interactions-v1.yaml`)
is ready and should not be run on LM loss. Finding 2 above is why: the objective
cannot resolve most of what the study would rank, and no seed count fixes a
non-responsive objective. It becomes viable with a structured objective, or with
the ablation delta as a post-hoc response variable — that delta is already
recorded per trial, so the second option needs no code.

**Rank / placement / SKA-layer-count sweeps** are gated behind a functional
anchor that does not yet exist.

  has no existing equivalent.

The lesson, stated for whoever picks this up: **read `code-tests/` before
proposing anything.** It contains more machinery than the module docstrings
suggest.

## Hazards this session added to the list in HANDOFF-2026-08-21 §6

- **A shared constant feeding an optuna `CategoricalDistribution` is a
  backward-compatibility surface.** Widening it breaks resume with
  `ValueError: does not support dynamic value space` — at `ask()`, after a worker
  has claimed a run root. And order is part of the support: `sorted()` over a set
  is a latent trap, because renaming a member can reorder it and break every
  existing journal.
- **Printing a status and continuing is not a check.** A script of mine printed
  `tree: 1 modified path(s) (0 wanted)` and proceeded, so the trainer refused a
  dirty tree 40 seconds later and the comparator got an empty log (job 447297).
  This is HANDOFF-08-21 §6's fourth pattern, and it recurs easily.
- **`squeue -h -t PENDING | wc -l` collapses an array range to 1.** Use
  `squeue -r`. A monitor reporting "1 pending" for 23 queued tasks is exactly the
  wrong number to let a partial arm be written up as finished.
- **Name the statistic, not just the job.** Two correct measurements of the same
  quantity differed 1.47x because one was 8 eval batches and the other 64, and
  they disagreed on whether a contrast was resolvable.
