### Two traps found while reading, currently unguarded

- **`--gradient-checkpointing` / `--compile` with `ska_prefix_scan: True`** dies
  with `cudaErrorStreamCaptureInvalidated` on H100 (job 415208, and it crashed
  identically with `ska_backend='pytorch'`, so it is not the CUDA kernel). This
  is documented *only* as a comment at `run/train_argv.py:91-106`. The teammate's
  driver defaults them off but offers them as opt-in flags with no warning — and
  they are exactly what someone hitting OOM reaches for. Candidate: promote to a
  `KoopmanLMConfig.__post_init__` assert, or at least a loud warning.
- **Eval batch size is coupled to the OOM outcome** in the driver
  (`min(eval_batch_size, successful_pdbs)`), so a trial that laddered down to
  `pdbs=1` reports `tokens_per_sec` / `peak_memory_gib` incomparable to its
  peers. Harmless while `--throughput-penalty 0`; poisons the objective the
  moment that is turned on.

### Scientific caveat worth stating out loud

Measured across the default search space (ranks 8/16/24/32 × counts 2/3/4/6/8):
parameter counts span **49,069,424 → 51,963,284, a 5.9% spread**, and
`--parameter-penalty` defaults to **0**. So by default this searches for the best
config, not the best config *at matched capacity*. Modest, but matched capacity
is the claim a paper needs. The knob exists; it is off.

**Corrected 2026-08-19**, once the complete harness arrived. I had flagged a
concern that at `--n-trials 15` with 15 anchors enqueued, TPE would contribute
nothing and `hybrid` would collapse into `curated15`. The previously-truncated
`main()` answers it: `hybrid` enqueues `min(8, n_trials)` and `curated15`
enqueues `min(15, n_trials)`, so hybrid leaves 7 of 15 slots for TPE and does not
collapse. `curated15` *is* all-anchors, which is what its name says. The concern
was unfounded for the mode that matters.

What remains true: 7 TPE trials is a thin budget for an 11-dimensional space, so
most of the signal at n=15 comes from the curated points either way — still the
argument for doing A0 first.

## G. Where adaptive search lives — decided 2026-08-19

**Inside `experimentation/sweep/`, as a nested `search/` subpackage.** Not a
sibling top-level package.

Two facts settled it:

- `sweep/__init__.py` is **docstring only** — it imports no submodules. So
  optuna-importing modules placed inside `sweep/` cannot break
  `import experimentation.sweep` or `python -m experimentation.sweep` when optuna
  is absent. The optional-dependency objection to co-location does not survive
  contact with the file.
- `experimentation/training/data/` is already a nested subpackage, so there is
  in-repo precedent for the shape.

And one design argument: `_materialize_cell` is currently private inside
`sweep/__main__.py`, and the search driver needs *exactly* that function. A
sibling package would have to import from a `__main__` module (a smell),
duplicate it, or force the promotion anyway. Co-locating makes the shared
helper natural rather than awkward. Files that change together live together.

The objection to co-location was that `sweep/spec.py`'s docstring declares "the
sweep grid is declared exactly once," statically — which adaptive search
contradicts. That is prose, not architecture. The honest reframing: for a static
sweep the invariant is *the grid is declared once*; for adaptive search it is
*the space is declared once*. Same anti-drift principle, one level up. Update the
docstring; don't fork the package.

### Layout

```

  spec.py            212   unchanged -- static grid: SweepSpec, expand_cells
  launch.py          ~90   NEW -- _materialize_cell promoted out of __main__.py,
```

Nesting also removes a name collision: a flat layout would put `spec.py` next to
`space.py`, which differ by one character and mean different things.

**The organizing principle: the split follows the optuna-dependency boundary.**
Only `study.py` and `driver.py` import optuna. `geometry.py`, `space.py`, and
`anchors.py` are pure — testable in the existing CPU suite with no new
dependency, which is why A0 can ship real science before optuna is ever
installed. If optuna is later swapped for Ax or Ray Tune, two files change.

### Working method

- **One worktree for the whole stack**, not one per commit: the stack is
  sequential (7 gates 14; F2 gates A1; eval-loader gates probes; D last).
  Worktrees buy isolation for *parallel* work, and there is little here.
  Created via the native `EnterWorktree` tool, not `git worktree add` — bypassing
  the native tool creates state the harness cannot manage, which is plausibly how
  23 worktrees accumulated across `.worktrees/` and `.claude/worktrees/`.
- **Throwaway worktree per attempt for E only.** Porting is trial-and-error;
  `stash@{0}` ("aborted PR B cherry-pick trial") already is one.
- **Genuinely parallelizable, if ever wanted:** commits 1, 3, 4, 6, 8 touch
  non-overlapping files. Merging five branches costs more than doing them
  serially.

### Verification hazard, found while setting up

`.venvs/koopman-cpu` has `koopman_lm` installed **editable, pointed at the main
checkout** (`__editable___koopman_lm_0_6_0_finder.py` → `/users/jkli/Koopman_Mamba/koopman_lm`).
From a worktree, imports resolve to the worktree only because cwd outranks the
`.pth` finder. Since this suite imports inside test bodies and some tests

`PYTHONPATH` to the worktree root, or `pip install -e .` inside the worktree,
before trusting any run.** Baseline confirmed in-worktree at HEAD `a4850de`:
499 passed, 28 skipped.
